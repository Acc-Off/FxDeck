# UI/UX メモ

関連: [DesignNote.ja.md](./DesignNote.ja.md)

仕組みは設計メモに任せ、ここでは「利用者が何を見て、何をするか」を言語化する。末尾 §9 に決定事項をまとめている。実装後の画面は [../README.md](../README.md) のスクリーンショット（`images/`）を参照。

## 0. 基本方針: Stream Deck Mobile に倣う

デッキ画面の見た目・操作感は **Elgato Stream Deck Mobile を基準**にする。利用者の多くが Stream Deck の流儀を知っている前提で、独自の工夫より「見慣れた形」を優先する。具体的には:

- 黒背景に **角丸の正方形キー**が等間隔に並ぶ。キーの中身は画像（アイコン）がキー全面を占め、タイトルはその上に重ねる
- テーマは **ダークが既定**（Stream Deck の見た目に合わせる）だが、**ライトにも切り替えられる**（§4.10）

見た目は Stream Deck Mobile 風で十分に想像できるため、**HTML モックは作らない**。実装後の画面で確認する。
- **グリッドは固定サイズ**（例: 5×3）。行を無限に伸ばす方式ではなく、1 ページ＝1 枚のデッキ
- **横向きが基準**（物理 Stream Deck と同じ並び）、縦向きでは行列を転置して表示
- 空きキーも暗いタイルとして描画する（「そこにキーがある」感を出す）
- ページ切り替えは左右スワイプ。フォルダキー（押すとサブページへ）は将来対応
- 設定は PC 側だけで行い、スマホは表示と押下に専念する

意図的に Stream Deck Mobile と変える点:

- 接続は LAN 自動探索ではなく **QR**（ブラウザ／PWA なので Bonjour が使えない。代わりに端末を選ばない）
- ネイティブアプリではなく PWA。ホーム画面追加で全画面化する
- サブスク不要・ハード不要

## 1. 利用者と利用シーン

- **利用者は 1 人**（自分の PC に自分のスマホを繋ぐ）。マルチユーザー・権限管理は考えない。
- **デッキ画面**: ゲーム中、PC の横に置いたスマホを**見ずに、あるいは一瞥して**片手（親指）で押す。暗い部屋・夜が多い。
- **管理画面**: ゲームをしていない時に PC のブラウザで、マウスとキーボードで落ち着いて編集する。
- 2 つの画面は利用状況が全く違うので、**共通デザインにこだわらない**。デッキは「押しやすさ」、管理は「編集しやすさ」を最優先。

## 2. 用語

| 用語 | 意味 |
|---|---|
| デッキ | スマホに表示されるボタン盤全体 |
| プロファイル | ボタンの集合＝デッキの 1 ページ。スワイプで切り替える単位 |
| ボタン | 1 マス。ラベル・アイコン・色・コマンドを持つ |
| コマンド | FiveM コンソールに送る文字列（`;` チェーン、`{500ms}` 可） |

「ページ」という語は使わず「プロファイル」に統一する（fxcommands 側の語彙に寄せる）。

## 3. 画面一覧

### デッキ側（スマホ）

| 画面 | 役割 |
|---|---|
| デッキ | ボタン盤。ほぼこれだけ |
| 接続待ち／切断オーバーレイ | WebSocket が切れている間の全面表示 |

### 管理側（PC ブラウザ）

| 画面 | 役割 |
|---|---|
| 接続 | 起動直後に開くホーム。ゲーム接続状態、LAN/トンネルの QR、初回セットアップの案内 |
| プロファイル | プロファイル一覧とボタン編集（グリッド＋プロパティパネル） |
| 設定 | ゲーム接続先、ポート、アダプタ、トンネル、自動起動、トークン再発行 |

### トレイ

- 右クリックメニュー: 管理画面を開く／デッキ URL をコピー／データフォルダを開く（config.json・ログ・画像がある `%LOCALAPPDATA%\FxDeck` をエクスプローラーで）／トンネル 開始・停止／（状態表示: FiveM 接続中・未接続）／終了
- 左クリック（ダブルクリック）: 管理画面を開く
- アイコン: 未接続＝グレー、接続中＝カラー

## 4. デッキ画面

### 4.1 レイアウト

横向き（基準）:

```
┌────────────────────────────────────────────────────┐
│ ● 接続中                 Default                 ▤ │ ← ステータスバー（極薄。設定で非表示可）
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│  │  👋  │ │  🚗  │ │  🔧  │ │      │ │      │     │
│  │ Wave │ │ Car  │ │ Fix  │ │      │ │      │     │ ← 空きキーも暗いタイルで描画
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘     │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│  │  📻  │ │ ⏻    │ │      │ │      │ │      │     │
│  │Radio │ │ Quit │ │      │ │      │ │      │     │ ← 長押しキーは右上に小さな印
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘     │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│  │      │ │      │ │      │ │      │ │      │     │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘     │
│                    ●  ○  ○                         │ ← ページインジケータ
└────────────────────────────────────────────────────┘
```

- **グリッドは固定サイズ**。プロファイルごとに列×行を選ぶ。プリセットは Stream Deck 系列に合わせる:
  - 3×2（Mini 相当）／**5×3（標準・既定）**／8×4（XL 相当）／カスタム
- **横向きが基準**。縦向きにした場合は行列を転置（5×3 → 3×5）し、読み順（左→右、上→下）を保つ。Stream Deck Mobile と同じ挙動。
- キーは常に正方形。画面に収まるようにキーサイズを算出し、余白は均等に配る。
- 空きキーも背景よりわずかに明るい（ライト時は暗い）タイルとして描画する。
- 背景はテーマ依存（ダーク: 黒、ライト: 明るいグレー）。§4.10 参照。
- ステータスバーは極薄で、設定で非表示にできる。非表示時の接続状態はキー全体の明度（未接続＝暗く）で表す。

### 4.2 キーの見た目

Stream Deck のキーは「72×72 の画像 1 枚」であり、それに倣う。

- キー全面が**アイコン領域**。背景色（ユーザー指定、既定は暗いグレー）の上に MDI / FA / 絵文字を大きく中央配置。ユーザー画像の場合は画像がキー全面を埋める（`object-fit: cover`）。
- **タイトルはオーバーレイ**。位置は 上／中／下（既定: 下）、表示／非表示を選べる。白文字に薄い影を付けてどんな背景でも読めるようにする。最大 2 行、溢れは省略。
- アイコン無しのキーはタイトルを中央に大きく表示。
- 長押しで実行するキーは右上に小さな印（●）を出す。
- キー角丸は大きめ（Stream Deck Mobile の見た目に近づける）。

### 4.3 押した時の挙動（最重要）

- **指を離したとき（タップ確定時）に送信する。** Stream Deck Mobile と同じ。押下開始から 10px 以上動いたらそのキーはキャンセルし、横方向ならスワイプ（§4.5）として扱う。これにより**どのキーの上からでもスワイプでページを送れる**。
  - 当初は `pointerdown` で送る案だったが、懸念していた「`click` の 100〜300ms 遅延」はダブルタップズーム判定のための `click` 固有のもので、`touch-action: none` にしているデッキでは発生しない。`pointerup` で送る実コストは指がキーに触れている時間（通常 100ms 前後）だけなので、スワイプとの両立を優先した（2026-08-30 変更）。
- 押下の瞬間: ボタンをわずかに縮小＋明度を上げる（CSS のみ、通信を待たない）。
- 触覚: `navigator.vibrate(10)`（対応端末のみ。iOS Safari は非対応なので視覚だけで完結させる）。
- 送信結果:
  - 成功（サーバーが FiveM へ書き込めた）: 何も出さない。成功が普通なので邪魔しない
  - 失敗（FiveM 未接続など）: ボタンを赤く一瞬点滅＋ステータスバーに理由をトースト表示
- チェーン（`{500ms}` を含む長いマクロ）実行中はボタンの下端に細い進捗バーを出し、実行中に再度押しても**多重実行しない**（無視）。
- **ホールドキー**（「離したとき」のコマンドを持つキー。設計メモ §3.2）だけは例外で、**押した瞬間**に `command` を送り、**離した瞬間**に `releaseCommand` を送る（押している間 `e sit`、離すと `e c`）。指がずれてスワイプになっても、画面から外れても、ページが切り替わっても、必ず `releaseCommand` は送る（押しっぱなし事故を防ぐ）。押している間はキーを押下表示のままにする。
  - 長押し確認（§4.4）と併用したときは、リングが一周した時点で `command`、離した時点で `releaseCommand`。
  - 通信が切れた場合はサーバー側が押しっぱなしのキーを離したものとして扱う。

### 4.4 長押し確認

- ボタンごとに「長押しで実行」フラグ。既定 OFF。
- ON のときは 600ms 押し続けるとリング状の進捗が一周して実行。途中で離すとキャンセル。
- `quit`、`disconnect` など取り返しがつかないコマンド向け。管理画面でコマンドにこれらの語を含むと「長押しにしますか？」と提案する程度の親切さはあってよい。

### 4.5 プロファイル（ページ）の切り替え

- **左右スワイプ**で隣のプロファイルへ（Stream Deck Mobile のページ送りと同じ）。下部にドットインジケータ。
- ドットをタップしても切り替えられる。
- 最後に表示していたプロファイルを端末側（localStorage）で記憶し、次回起動時に復元する。
- **フォルダキー**（押すとサブページへ入り、左上に戻るキーが現れる）と「特定のプロファイルへ飛ぶキー」は将来機能。MVP では作らないが、キーの `action` を `command` 以外にも拡張できるデータ構造にしておく。

### 4.6 ステータスバー

- 左: 接続状態ドット＋短いテキスト（`FiveM 接続中` / `FiveM 未接続` / `再接続中…`）
- 中央: プロファイル名
- 右: コンソール引き出しの開閉アイコン

### 4.7 接続状態ごとの表示

| 状態 | 表示 | ボタン |
|---|---|---|
| WebSocket 接続中・FiveM 接続中 | 通常 | 押せる |
| WebSocket 接続中・FiveM 未接続 | ステータスバーが黄色「FiveM 未接続」 | 半透明で押せる。押すと「FiveM が起動していません」トースト |
| WebSocket 切断（PC 側停止・ネットワーク断） | 全面オーバーレイ「再接続中…」＋経過秒。自動再接続を続ける | 押せない |
| トークン無効（再発行された） | 全面「アクセスが無効になりました。PC の管理画面で QR を読み直してください」 | 押せない |

FiveM 未接続でもボタンを押せるようにするのは、「ゲームを起動する前にスマホを準備しておく」流れを止めないため。

### 4.8 コンソール引き出し

- 画面下端から引き上げる（またはステータスバー右のアイコン）。
- 直近 200 行の `PRNT` 出力を等幅で表示。自動スクロール、指で触ると追従停止。
- 既定は閉じている。開閉状態は端末側で記憶。
- ステータスバーを非表示にしている場合は、右下の小さなハンドル `>_` から開く。
- 引き出しの中: 上部に「コンソール」「最新へ」（追従停止中のみ）「✕」、下は行のリスト。空のときは「FiveM のコンソール出力がここに流れます」。
- スマホでコンソール文字を打つ「入力欄」は MVP では作らない（将来: 自由入力コマンド）。

### 4.9 PWA と復帰

- 初回表示時に控えめなバナー「ホーム画面に追加すると全画面で使えます」＋ OS 別の手順（iOS: 共有 → ホーム画面に追加／Android: インストールプロンプト）。閉じたら二度と出さない。
- ホーム画面から起動 → Cookie で認証済み → 即デッキ表示。トークン交換画面は原則見せない。
- Cookie 有効期限は 90 日のスライディング（使うたび延長）。
- `Screen Wake Lock` で表示中はスリープしない。バックグラウンドから復帰した時は WebSocket を張り直す。

### 4.10 テーマ

- **ダーク／ライト／システムに従う** の 3 択。既定は **ダーク**（Stream Deck ユーザーに馴染む見た目）。
- 設定は管理画面の「設定 → アプリ → テーマ」の 1 箇所で行い、**管理画面とデッキの両方に適用**する（利用者は 1 人なので端末ごとの切り替えは持たない）。デッキにはプロファイルと同じ WebSocket で即時に反映する。
- デッキのライトテーマ: 背景は明るいグレー、空きキーはそれより少し暗いタイル、ステータスバーは黒文字。キー自体の背景色（ユーザー指定）とタイトル（白＋影）はテーマに関係なく同じ見た目にし、テーマ切替でキーの印象が変わらないようにする。
- 管理画面のライトテーマ: 一般的な白基調。プレビューグリッドはデッキと同じテーマで描画し、実機と見た目を揃える。
- 「システムに従う」は `prefers-color-scheme` を見る（PC とスマホで別々の結果になりうるが、それが利用者の意図）。

### 4.11 ステージキー

- 押すたびに次のステージ（最大 5）へ進み、見た目（アイコン・タイトル・背景）とコマンドが切り替わる。代表例は「座る／立つ」のトグル（1: `e sit`、2: `e c`）。
- ステージは PC 側が持ち、**同じデッキを開いているすべてのスマホで一致**する。FxDeck を再起動すると 1 に戻る。
- 送信に失敗したときはステージを進めない（押しても何も起きなかった状態と一致させる）。
- キーの左上に現在ステージを示す小さなドット列（ステージ数ぶん、現在位置だけ明るい）を出す。見た目が同じステージでも今どこにいるか分かるようにするため。長押しの印（右上）とは反対側。
- 管理画面でそのキーを編集してステージ数が減り、現在位置が範囲外になったときも 1 に戻る。

### 5.2 接続（ホーム）

起動直後にブラウザで自動的に開く画面。

```
┌─────────────────────────────────────────────────────┐
│ スマホから接続する                                    │
│                                                     │
│  ┌─────────┐  同じネットワークから  ┌─────────┐ 別ネットワークから│
│  │  QR     │  http://192.168.1.5   │  QR     │ （トンネル: 停止中）│
│  │  (LAN)  │  :20200               │ (トンネル)│ [トンネルを開始] │
│  └─────────┘  [URL をコピー]        └─────────┘                  │
│                                                     │
│ ▸ スマホから開けない場合                              │
│    ・Windows ファイアウォールで許可されているか  [許可する]  │
│    ・PC とスマホが同じネットワークか（モバイル回線、ゲスト Wi-Fi、AP 分離に注意）│
│    ・それでも駄目なら「別ネットワークから」のトンネルを使う   │
│                                                     │
│ 初回セットアップ                                      │
│  ☑ FiveM を起動する          （接続を検知すると自動でチェック）│
│  ☐ ファイアウォールを許可する   [許可する]                │
│  ☐ スマホで QR を読む         （デッキが接続すると自動でチェック）│
└─────────────────────────────────────────────────────┘
```

- QR は 2 つ並べる。トンネル側の表示は状態で変わる:
  - 停止中: グレーの QR 枠＋「トンネルを開始」ボタン。設定のモードが「使わない」でも押せる（TryCloudflare で一時的に開始する。設定は変えない）
  - 開始中: 枠に「開始しています…」（初回は cloudflared のダウンロードが入るので数十秒かかる旨を添える）。ボタンは無効
  - 稼働中: トンネル URL の QR、URL（トークンなし）、「URL をコピー」「トンネルを停止」。TryCloudflare は「URL は起動ごとに変わります」と注記
  - 失敗: 枠に理由（ダウンロード失敗／起動失敗／予期せず終了）を分けて表示し、「再試行」ボタン
  - 固定 URL モードで `namedUrl` が未設定: 稼働はするが QR は出せないので「設定で固定 URL を入力してください」
- 初回セットアップのチェックリストは、**全部済むと畳まれる**（消えはしない）。
- 「ファイアウォールを許可する」の仕組み:
  - 管理画面は `127.0.0.1` で見ているので、Windows Firewall の許可有無に関係なく**常に表示できる**（受信ルールは loopback に効かない）。許可が要るのはデッキ用ポートへの LAN からの通信だけ。
  - ブラウザが localhost 限定の管理 API を叩き、**FxDeck プロセス側が `netsh` を `runas` で起動**して UAC ダイアログを出す（ブラウザは昇格しない）。結果（成功／キャンセル）を画面に表示する。
  - 通常は初回 Listen 時に Windows が自動で出す「セキュリティの重要な警告」で許可すれば済む。このボタンは、そのダイアログをキャンセルした／裏に隠れて気付かなかった場合の復旧用。
  - チェック状態は `netsh advfirewall firewall show rule name="FxDeck"` の結果で判定する。
- QR には**トークンが入っている**ことを小さく注記し、「QR を無効化（トークン再発行）」へのリンクを置く。

```
│  ├────┼────┼────┼────┼────┤    │          ; で連結、{500ms} で待機│
│  │    │    │    │    │    │    │  ☐ 長押しで実行              │
│  └────┴────┴────┴────┴────┘    │                              │
│  スマホと同じ見た目（横向き）     │  [テスト送信]  [キーをクリア]   │
│                                │  ✓ 保存済み・デッキに反映済み   │
└────────────────────────────────┴──────────────────────────────┘
```

- 左: **スマホと同じ描画のプレビュー**（横向き基準、黒背景、正方形キー）。空きキーは暗いタイル。クリックで選択、右のパネルで編集。
- ドラッグ＆ドロップで移動（空きキーへ）／入れ替え（埋まっているキーへ）。
- サイズは 3×2／5×3／8×4／カスタム。縮小時にはみ出るキーがある場合は警告し、確認後に切り捨てる。
- 右: 選択中キーのプロパティ。項目は **ステージ → タイトル（位置・表示）→ アイコン → 背景色 → コマンド → 離したときのコマンド → 長押し** の順（見た目 → 動作）。
  - **ステージ**: パネル先頭に `1 2 3 … +` のタブ。既定は 1 つだけで `+` で増やす（最大 5）。タブ 1 はキー本体の見た目とコマンド、タブ 2 以降はそのステージの見た目とコマンド（増やしたときはタブ 1 の見た目をコピーして始める。以降は独立）。タブの右端に「このステージを削除」。プレビューはステージ 1 の見た目＋左上のドット列で描く。
  - **離したときのコマンド**: 「コマンド」の下に小さめの入力欄「離したとき（任意）」。入れると「押した瞬間に上、離した瞬間にこれを送ります」とヒントを出す。
  - 「テスト送信」は表示中のタブのコマンドを送る。離したときのコマンドがあるときは「離すをテスト」も並べる。
- 背景色は 8〜12 色のプリセット＋カスタム。既定は暗いグレー。タイトル文字は白＋影で固定。
- **「テスト送信」**でその場で FiveM に送れる（ゲーム起動中なら）。編集中に動作確認できるのが重要。
- **保存は自動**（入力停止 500ms 後）。右下に「保存済み・デッキに反映済み」を表示。接続中のスマホには WebSocket で即時プッシュされ、**編集しながらスマホで押して確かめられる**。
- `[⋯]` メニュー: 名前変更／複製／エクスポート（このプロファイルのみ）／削除。
- `[+]` で新規プロファイル。空のプロファイルは「キーをクリックして最初のキーを設定」の空状態案内を出す。
- プロファイルの並び順（スワイプ順）はセレクタ内のドラッグで変える。

### 5.4 アイコンピッカー

- モーダル。上部に検索ボックス（フォーカス済み）、タブ: **すべて／MDI／Font Awesome／絵文字／画像**。
- 検索は 3 セット横断、入力のたびに絞り込み。結果はグリッドで、ホバーで名前。
- 「画像」タブ: ドラッグ＆ドロップまたはファイル選択でアップロード。既にアップロード済みの画像も一覧に出す。
- 最近使ったアイコンを検索ボックス直下に 10 個ほど出す。

### 5.5 設定

グループ分けして 1 ページに縦に並べる（タブにしない）。

| グループ | 項目 |
|---|---|
| FiveM 接続 | ホスト、ポート（既定 127.0.0.1:29200）、「接続テスト」 |
| デッキ | ポート（既定 20200）、使用するネットワークアダプタ（自動／一覧から選択） |
| トンネル | モード（使わない／TryCloudflare／固定 URL）、固定 URL 用のトークンと公開 URL（固定 URL のときだけ表示）、起動時に自動開始。モードや固定 URL の変更は次回の開始から効く（稼働中なら「再起動して反映」ではなく「停止→開始」を案内） |
| セキュリティ | デッキトークンの再発行（確認ダイアログ付き。「接続中の全スマホが切断されます」） |
| アプリ | Windows 起動時に自動起動、テーマ（ダーク／ライト／システム）、言語（自動／日本語／English。管理画面とデッキ共通、DesignNote §3.9）、デッキのステータスバー表示 |
| データ | 全体エクスポート（.fxdeck）、インポート、未使用画像の削除 |

変更は即時保存。ポート変更など再起動が必要なものは「再起動して反映」ボタンを出す。

## 6. 主要フロー

### 6.1 PC 初回起動

1. exe 実行 → トレイに常駐 → **既定ブラウザで「接続」画面を自動で開く**（初回のみ。2 回目以降は開かず、トレイのバルーンで「起動しました」）
2. 「接続」画面の初回セットアップに従う。ファイアウォールのダイアログが OS から出た場合もここで「許可する」を押せばリカバリできる
3. FiveM を起動すると、ナビ下部の状態が「接続中」に変わりチェックが付く

### 6.2 スマホ初回接続

1. 「接続」画面の LAN 用 QR をカメラで読む
2. ブラウザが開く → `?t=` をサーバーで Cookie に交換 → URL からトークンが消える → デッキ表示
3. 「ホーム画面に追加」バナー → 追加 → 以降はアイコンから全画面で起動
4. PC 側の「接続」画面ではチェックリストの最後が自動で埋まる

### 6.3 繋がらない

1. QR を読んでもブラウザがタイムアウト
2. PC の「接続」画面の「スマホから開けない場合」を開く → ファイアウォール許可 → 同じネットワークかを確認
3. それでも駄目 → 「トンネルを開始」→ トンネル用 QR が出る → それを読む

### 6.4 ボタンを作る・直す

1. 管理画面「プロファイル」→ 空きマスをクリック → 右パネルで入力
2. 「テスト送信」で確認、またはスマホで押して確認（即時反映）
3. 保存操作は不要

### 6.5 いつも通り使う

1. PC 起動時に自動起動（設定 ON の場合）→ トレイに入る
2. FiveM 起動
3. スマホのホーム画面アイコンをタップ → 即デッキ表示 → 押す

### 6.6 トークンを再発行する

1. 設定 → セキュリティ → 再発行 → 確認
2. 接続中のスマホは「アクセスが無効になりました」画面になる
3. 「接続」画面の QR が新しくなるので読み直す

## 7. エラー・空状態の一覧

| 場面 | 表示 |
|---|---|
| プロファイルが 0 個（デッキ） | 「PC の管理画面でボタンを追加してください」 |
| ボタンが 0 個のプロファイル（デッキ） | 中央にプロファイル名と「ボタンがありません」 |
| ボタンが 0 個のプロファイル（管理） | グリッドの上に「最初のボタンを追加」の案内 |
| FiveM に送信失敗（デッキ） | ボタン赤点滅＋トースト「FiveM が起動していません」（ホールドキーは押した／離したのどちらで失敗しても同じ表示） |
| コマンドが空のキーを押した（デッキ） | 赤点滅＋トースト「コマンドがありません」。作りかけのキーは保存できるので起こりうる |
| インポート失敗（管理） | ファイル形式／バージョン不一致を具体的に表示。部分的に取り込まない |
| インポートで画像が見つからない（管理） | 取り込みは成功、警告「N 個のボタンの画像が見つからずラベル表示になります」 |
| トンネル起動失敗（管理） | cloudflared のダウンロード失敗／起動失敗を分けて表示、再試行ボタン |
| ポート使用中（起動時） | トレイのバルーンで通知し、管理画面の設定で別ポートに変えられるようにする（管理画面自体は動的ポートなので開ける） |

## 8. 設計メモへの影響

- 「押した時の挙動」のため、WebSocket メッセージに**ボタン押下の結果（成功／失敗理由）を返す**必要がある（DesignNote §3.3 の `status` に含める、または `result` を追加）。
- 管理画面の「編集を即時プッシュ」のため、プロファイル更新時にデッキ用 WebSocket へ `profile` を送る（既に記載あり）。
- 「テスト送信」用に管理 API `POST /api/admin/send` を追加。
- 「接続テスト」「ファイアウォール許可」用の管理 API を追加。
- プロファイルは `columns` ではなく **`columns` + `rows` の固定グリッド**。並び順を持つ。
- キーに `holdToConfirm: bool`、`title: { text, position: top|middle|bottom, visible }` を追加。`command` は将来のフォルダキー等に備えて `action: { type: "command", command: "…" }` の形にする。
- ホールドキー（§4.3）とステージキー（§4.11）のため、`action` に `releaseCommand` と `stages[]` を追加し、WebSocket に `release` / `stage` メッセージと `hello.stages` を追加（設計メモ §3.2 / §3.3 / §4）。
- 設定に `theme: dark | light | system`（既定 dark）と `deckStatusBar: bool` を追加。デッキ側へは WebSocket の `settings` メッセージで配る。

## 9. 決定事項（2026-08-30）

1. グリッドの既定は **5×3（横向き基準）**
2. 縦向きは**転置（3×5）**
3. 送信は **指を離したとき（タップ確定時）**。動いたらキャンセル＝スワイプ（2026-08-30 に `pointerdown` 即発火から変更。理由は §4.3）
4. FiveM 未接続時もキーは**押せる**（押すと注意トースト）
5. 保存は**自動保存**
6. ステータスバーは**極薄で常時表示・設定で非表示可**
7. テーマは**ダーク既定、ライト／システムに切替可**。HTML モックは作らない
